# 内部検討記録: 論点17 — 現在の正本の写しと、状態ごとの見本を Claude Design に作るか

**discussion:** [task-design-discussion.md](../task-design-discussion.md)

**論点:** 論点17

## 開始context

Phase 1〜6 の適用と本人の動作確認が終わった後、本人から、会社で Figma が持つような「現在の正本の写し」を artifact として作るかを問われた。
同じ問いの後半で、状態ごとの画面か部品のバリアントを表したものの群も作るかを問われた。

「正本の写し」は、全画面の現在の見た目を常に最新に保つ artifact を指す。
開始時の既決条件は次の二つである。

- 論点14: 正本はリポジトリに置き、Claude Design は作業場とする。常に同期する努力はしない。
- 論点13: 手書きの部品のプレビューは、画面を変えるたびにずれるため Design System へ入れない。

この記録は事後記録である。
答えはチャットで示し、本人の応答を受けた後に書いた。

## イテレーション0: 写しと見本を作るか

チャットでの答え、本人の応答、`tasklist.md` の「確定案のボードとの差の記録」を根拠に使う。

<a id="iteration-0-record-1"></a>

### 判断: 正本の写しを Claude Design に作るか

#### 判断対象・必須条件・根拠

作らないことを推した。決め手は論点14の決定との整合である。

必須条件は、論点14の決定と矛盾しないことである。
比較軸は、写しが実物とどれだけずれるかと、保つ手間である。
根拠は、論点14の決定と、今回キャンバスからコードへ移した時の差の記録である。

#### 当てた結果

- 論点14で正本をリポジトリに置いたため、写しを正本として保つと二重の正本になる。
- 写しはコードを HTML で作り直したものである。今回、確定案のボードからコードへ移した時に、修正を要する差が11点出た。逆向きに写す時も同じ種類の差が出る。
- 全画面を最新に保つと、画面を変えるたびに写し直す手間がかかる。古くなった写しは、無い時より誤った判断を招く。

代わりに、議論を始める時に対象の画面の現状をコードから作る。今回の「現状」のボードと同じである。
実物どおりの写しが要る場合は、実部品をキャンバスへ置く方法（論点13で示した段階3）が要る。今は使わない。

<a id="iteration-0-record-2"></a>

### 診断: 状態ごとの見本の問いを、別の問いと読んだ

#### 期待との差と原因候補

本人の問いの後半に、私は前半と別の問いとして答えた。
状態ごとの画面は確定案の page にあると答え、部品のバリアントは Phase 7 で今回触ったカレンダーの部品の見本を Design System へ置く案を推した。

本人の応答は、後半は前半の写しにバリアントまで含めるかを聞いていた、というものだった。

#### 原因

原因は問いの読み違いである。
後半を前半へ付け足された問いと読まず、Design System の機能を試す機会として読んだ。

加えて、論点13の「手書きの部品のプレビューは入れない」を参照していなかった。
この決定は `design.md` の「Claude Design の Design System」にも書かれている。

共有知識の不足ではなく、今回の回答だけの逸脱である。
そのため文書の修正へは回さない。

#### 修正

部品の見本の案を撤回し、Phase 7 の範囲を変えない。

<a id="iteration-0-record-3"></a>

### 判断: 決定の反映後に、repository の文書へ残す知識があるか

#### 判断対象・必須条件・根拠

決定を `design.md` の非目標へ反映した後、doc-enricher の提案 mode の手順と Gate A〜G を当てた。
doc-enricher の skill は改めて起動しておらず、この session で読んだ手順を私が当てた。

候補は、`ui_design_management.md` へ「全画面の正本の写しを作業場に作らない」を足すことである。

#### 当てた結果

候補なしとした。

- Gate G（既存文書との非重複）で落ちる。`ui_design_management.md` は、正本をリポジトリに置き、Claude Design を作業場とし、`tokens.json` などを正本にせず、常に同期する努力はしないと既に定めている。写しを作らないことは、この方針から導ける。
- 今回の誤りは問いの読み違いと既決事項の見落としであり、この文書の不足から生じたものではない。「やってしまいがちな失敗」へ足す具体例にも当たらない。
