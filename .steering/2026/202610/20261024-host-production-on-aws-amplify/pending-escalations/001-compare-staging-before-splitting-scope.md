# 保留メモ: 範囲を別作業へ出す前に、同じテーマ内の段階化と比べる

## 保留時の内容

**提案:** plugin の `task-design/SKILL.md` の「3-5. 実行して初めて確定することは、段階を分けて設計する」へ次を追加する。

- 違反シグナルに追加: 「合意済みの範囲の一部を別の作業へ出す提案をしているが、分けないと何が困るかを言えず、同じテーマ内で段階を分ける形（roadmap の後段 phase）と比べていない。決める事項の多さを分ける理由にしている」
- 帰結に追加: 「範囲の外へ出すと、その作業を行う義務がテーマから消え、干渉しない場所へ追い出しただけになる。決める事項が多くても、参考元をほぼ踏襲できるなら負担にはならず、分ける理由にならない。」
- 問いに追加: 「「分けないと何が困るか。それを満たす分け方は、範囲の外へ出す以外にないか?」」

**具体例:** 参考元 repository の構成を踏襲する作業で、合意済み範囲のうち後段の移行（Terraform の適用経路の変更）を「決める事項が多い」という理由で別 steering へ出す提案をした。利用者から、別 steering は干渉しない場所への追い出しに見えること、roadmap 等と比べていないこと、ほぼ踏襲なら事項が多くても負担ではないことを指摘された。分ける本当の理由は「後段の設計完了まで前段の実行を待たせない」であり、roadmap の二 phase で満たせた。

**根拠:** 範囲を分ける判断は、分けないと何が困るかで決まる。その理由を満たす分け方は範囲外への移動だけではない。比較を飛ばすと、後段の作業を行う義務がテーマから消える。docs の再構成で「残りの章は別タスクで」と言いたくなる場面など、別の分野でも同じ問いが効く。
