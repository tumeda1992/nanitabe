# RV-024: 動作確認環境の起動途中失敗が自動停止なしの状態を残す

## 問題と根拠

desired-countを1にした後、services-stable待機、task/ENI/IP取得、API integration更新はset -eで終了するがrollback処理を呼ばない。rollbackが定義され使われるのは後半のschedule作成付近だけ。初回起動の待機やAPI操作で失敗すると自動停止scheduleがまだない状態でdesired-count=1を残し、再実行は「既に起動中」で早期終了する。

## 改善案

起動の副作用を開始する前に失敗時cleanupを登録し、schedule確立までの失敗・中断を停止側へ戻す。既に起動中の判定でもscheduleの有効性を確認する。cleanup失敗も明示的に報告する。

## 振る舞いを維持する条件

失敗時の運用挙動変更のため対象外。起動成功時の停止までの時間や、再起動による延長可否は別途維持すべき契約として決める。

## 検証方法

AWS CLIをstub化し、desired-count更新後の各段階へ失敗を注入して停止処理が呼ばれることを確認する。stub検証では実AWSを変更しない。
