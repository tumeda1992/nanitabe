## 問題と根拠

curl -X GETのみでHTTPステータスを失敗に変えるオプションがない。接続が成功してHTTP 401/500を返した場合、curlは通常終了コード0で終了し、deploy要求が失敗してもworkflowは成功表示になる。

## 改善案

--failと--silent --show-error、接続/全体timeoutを設定する。レスポンス本文を公開logへ出す必要はないため出力先も限定する。再試行はwebhookの冪等性を確認してから決める。

## 振る舞いを維持する条件

失敗判定とtimeoutが変わるため対象外。応答成功はデプロイ完了そのものを保証しない点も維持して記録する。

## 検証方法

ローカルのstubで200・401・500・timeoutを返し、終了コードとlogにsecretや本文が出ないことを確認する。実webhookは検証用に呼ばない。
