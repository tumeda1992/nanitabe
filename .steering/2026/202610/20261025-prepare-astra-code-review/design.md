# 振る舞いを維持するレビュー指摘の適用

## 目的と完成後の姿

レビューの今回対象8件を適用し、入力変換・フォーム・状態型・一覧取得の重複を減らす。ユーザーが観測する値、例外、処理順序、保存結果、表示と操作を維持する。適用対象外20件と要調査RV-016は自動適用しない。

## 合意と実行方針

2026-10-26の「適用しちゃって。1件解消ごとに自動テストは回す」に基づいて開始する。対象と改善方針の正本は各findingとREADME。各項目に必要なテストを先に確認・追加し、変更後の関連テスト成功を確認してから次へ進む。テストはDocker内で実行し、テストDBはSQLiteの分離DBを使う。実環境の設定・DBは利用しない。

## 変更単位と維持する契約

| 項目 | 変更 | 維持する契約と確認 |
| --- | --- | --- |
| RV-025 | food設計文書を開発標準へ合わせる | 実行コードは変更せず、リンクと現行mutationを照合しbackendの自動テストを実行 |
| RV-015 | モード定数をliteral化し共有型とsetter引数を指定 | 文字列・遷移・callback待機方法は同じ。切替とEscapeのhookテスト、型検査 |
| RV-014 | 正規化辞書の保存用属性生成を抽出 | createとupdate!、取得・正規化・反映の順序と回数、空destinationの代替、戻り値を維持 |
| RV-013 | GraphQL層に料理出典とタグの入力変換を抽出 | 集約間orchestrationとtransactionはresolverに残し、nilと空値の条件、food引数変換を維持 |
| RV-001 | frontendの既存/新規出典入力変換を抽出 | cloneの順序・非破壊性・余剰meal/frameEntryId保持、NO_VALUEのnull、detailType削除を維持。既存出典の料理更新は統合しない |
| RV-029 | 週/月カレンダーのURL日付解釈を抽出 | 現行正規表現、queryや不正形式時のfallback、09:00生成、形式検査のみという契約を維持 |
| RV-012 | 作成/編集フォームの共通入力操作を抽出 | 初期復元、ラベル・DOM順・選択肢・検証・payload・成功callbackを維持。編集専用specを追加 |
| RV-026 | パターン一覧の関連取得をまとめる | Hash出力、並び、空entries、欠落枠の空文字、ユーザー絞込を維持。応答テストとSQL数検査 |

RV-026は応答を維持しつつ問い合わせ回数を削減する。問い合わせ間の同時更新を含むスナップショットの厳密同一性は既存APIでも保証されず、今回新たな保証は導入しない。

## 対象外と終了条件

認可、不具合、非同期完了の変更を混ぜない。修正後に各指摘の採否・対応状況と検証結果を記録する。全件終了後に再発防止の文書更新を提案する。対象指摘の既存文書矛盾修正以外の予防規約は提案段階に留める。
コミット/pushは実装確認後の工程として扱い、本計画では追加実行しない。
