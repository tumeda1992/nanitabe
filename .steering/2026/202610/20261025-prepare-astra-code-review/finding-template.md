# RV-NNN: 指摘の内容が分かるタイトル

- 観点: 責務分離 / 重複 / 依存関係 / 命名 / その他から具体的に記入
- 優先度: 高 / 中 / 低（影響に基づく理由を本文に記入）
- 採否: 未判断
- 対応状況: 未着手
- 今回の適用対象: 対象 / 対象外 / 要調査
- 対象コミット: 完全なコミットSHA
- 対象: ファイルパス、関数・クラス名、対象コミットでの行番号
- 依存する指摘: なし、または関連指摘への相対リンク

## 問題と根拠

どこに何があり、なぜ問題なのか。コード上の具体例と、保守・理解・変更に与える影響を書く。
確認できた事実と推測を区別する。

## 改善案

どの責務をどこへ移し、どの呼び出しをどう変更するかを書く。
「分割する」「共通化する」だけで終わらせない。
安全な案を出せない場合は、その理由と必要な追加調査を書く。

## 振る舞いを維持する条件

戻り値、例外、処理順序、副作用、公開APIなど、今回変えてはいけない点を書く。
提案した変更で維持できる根拠と未確認の点を示す。
振る舞いの変更が必要な場合は「対象外」、維持可否が未確認なら「要調査」とする。

## 検証方法

使う既存テスト、必要な追加テスト、手動確認方法と期待する結果を書く。
未実行の確認を実行済みとは記載しない。

## 採否・対応記録

- ユーザーの判断・理由: 未判断
- 適用コミット: 未適用
- 検証結果: 未実行
