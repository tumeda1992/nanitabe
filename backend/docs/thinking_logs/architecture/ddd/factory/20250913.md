# Factoryにおける不変条件の保証とオブジェクト構築パターンの検討
## 結論

- ドメインオブジェクト（Dish::Root）の不変条件は常に守られるべきであり、一時的にも破られるべきではない
- 具体的には、コンストラクタで全ての属性を設定し、rootのinitialize内でvalidate!を呼ぶ方式を採用する
- source_idとsource_locatorなどの新しい属性も同様にコンストラクタで設定する
- normalized_nameのような派生値は値オブジェクトとしてカプセル化し、整合性を確保する

## 背景
- Business::Food::Dish::RootについてAddCommandをレシピ元紐付けとセットで改善しようとしていた
- 今まではDishテーブルのカラムをコンストラクタで入れていた。
- source_idとかもコンストラクタで入れるか、root作った後にセッターで値をセットするか迷った


## 議論・論点
ポジション
- A. インスタンスの不変条件が守られない状態がないように保つ（具体: コンストラクタで全部入れる）
- B. Factoryのメソッド終了時に不変条件が守られていればいい(具体: 途中で値をセットすることも許容する)
  - renameなどのセッターには不変条件チェックが入っているから便利
  - エラーが起きても、何行目とかわかりやすい

結果
- Aを採用
  - 不変条件を守りたい
    - Factoryを経由してのみDish::Rootを生成できるようにしているためBも取れるのは事実
    - だが、オブジェクトとして不変条件が守られない状態がありえるのは、バグやほころびが起こってもおかしくない
    - Aを前提として組める
  - 現状のセッターが、不変条件が守られている状態での値変更が多い
    - それを初期化に使うのは濫用

修正にあたってのtips
- source_idを入れるときに、セッターだとpolicyでのチェックをしているが、どう対応するか
  - FactoryでPolicyチェックを行う
    - DDDにおいてFactoryはドメイン知識を豊富に内包して問題ない存在のため
- initialize内でvalidate!を呼ぶ
