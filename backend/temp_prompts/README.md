# 一時的なプロンプト保存ディレクトリ

このディレクトリは、AIアシスタント（Cursor等）に対する一時的な指示やプロンプトを保存するための場所です。

## 使用目的
- 長文の指示や複雑なプロンプトの一時的な保存
- 複数のAIアシスタントセッションで再利用したい指示の保存
- 作業中のタスクに関する一時的なメモや指示の保管

## このファイルを利用した指示の仕方

```
次のファイルに従ってタスクを進めて欲しい。
temp_prompts/20250811_create_dish_source_root_and_command.md

その前に次のディレクトリの配下のルールファイルを読んで。軽くファイルを確認するのではなく、1ファイルずつ開いて読んで内容を覚えて。
docs/ai_guideline
```

## 進め方
- すでにこの後遂行したいタスクファイルがある場合
  - 「タスクの遂行プロセス」とタスクファイルの指示に従ってタスクを進める
- タスクファイルがまだない場合
  - 「タスクファイルの作成プロセス」を見ながらタスク整理をする。 


## タスクファイルの作成プロセス
次のように進めてほしい

- 作業全体のアウトラインを作成し、合意を得る
- アウトラインをフェーズに分割し、フェーズの進める順番を決め、合意を得る
- 各フェーズをさらにタスクに分解し、実装の指針を明確にする

### 作業全体のアウトラインを作成し、合意を得る
- タスク全体をどのように遂行するかのアウトラインを作成する
  - 細部にいきすぎずどのような流れでタスクを進めるかを大まかに示す
- 合意する
  - 合意なく勝手に次にステップに進んではいけない

### アウトラインをフェーズに分割し、フェーズの進める順番を決め、合意を得る
- アウトラインをフェーズに分解する
- フェーズの分け方について合意を得る。
- フェーズの進める順番を決める
  - フェーズの順番は、依存関係や優先順位に基づいて決定する
- 合意する
  - 合意なく勝手に次にステップに進んではいけない

分割基準
- 最小限の機能での実現可能性
- 技術的な独立性
  - 共通基盤との関係
  - テスト容易性
  - リスク管理

### 各フェーズをさらにタスクに分解し、実装の指針を明確にする
- 各フェーズをさらにタスクに分解する
  - タスクは実装可能な単位で、具体的なアクションを含む
  - タスクはテスト駆動開発に沿って記述する

#### タスク分解・順番考慮時の注意事項
遂行者が実際に実行可能なレベルでの詳細なタスクの記載をすること
- 悪い例：
  - APIの実装
- 良い例：
  1. POST /api/endpoint のテスト作成
  2. エンドポイントの実装
    - リクエストバリデーション
    - レスポンス形式の定義

レイヤごとに作らない
- 前提例
  - 機能がA,B,Cとある
  - レイヤーがドメインモジュール、API層、フロントエンド層、E2Eテストがある
- 悪い例（レイヤー順実装）：
  1. ドメインモジュールを全て実装
  2. API層を全て実装
  3. フロントエンド層を全て実装
- 良い例（機能サイクル実装）：
  1. 機能Aの最小実装
    - 必要なドメインロジック
    - 必要なAPI
    - 必要なUI
  2. 機能Bの最小実装
    - 必要なドメインロジック
    - 必要なAPI
    - 必要なUI
    - ...


## タスクの遂行プロセス
次のように進めてほしい

- 自分が今着手するタスクの確認
- テスト駆動開発に沿った実装
- 進捗内容の随時更新

### 自分が今着手するタスクの確認
今自分が着手するタスクやステップを明確にして作業を進める。
前のタスクが終わってないのに勝手に次のタスクには進まない。
タスクが終わり、タスクが終わったことを指示者と合意できてから進捗を更新してから次のタスクやステップに進む

### テスト駆動開発に沿った実装
a. テストの作成
- 修正意図に沿ったテストを作成
- テストは具体的なシナリオを記述
- テストは独立して実行可能

b. 実装の作成/修正
- テストを通すための最小限の実装
- テストの意図に沿った実装
- コードの品質を維持

c. テストの実行
- テストを実行して結果を確認
- 成功した場合：次のステップに進む
- 失敗した場合：
- エラーを分析
- 実装を修正
- cに戻る

d. 次のサイクルへ
- aに戻って次のテストケースの作成
- 全てのテストケースが成功するまで繰り返す


### 進捗内容の随時更新
- 完了したタスクのマーク
    - [ ] から [x] に変更
    - 完了したタスクの日付を記録




## 注意事項
- このディレクトリ内のマークダウンファイル（`*.md`）は`.gitignore`によってGit管理から除外されます
- `README.md`のみGit管理対象となります
- ドメイン知識や永続的に保存したい情報は`docs/`ディレクトリに保存してください
