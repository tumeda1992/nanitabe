# タスクリスト

## 🚨 タスク完全完了の原則

**このファイルの全タスクが完了するまで作業を継続すること**

### 必須ルール
- **全てのタスクを`[x]`にすること**
- 「時間の都合により別タスクとして実施予定」は禁止
- 「実装が複雑すぎるため後回し」は禁止
- 未完了タスク（`[ ]`）を残したまま作業を終了しない

### 実装可能なタスクのみを計画
- 計画段階で「実装可能なタスク」のみをリストアップ
- 「将来やるかもしれないタスク」は含めない
- 「検討中のタスク」は含めない

### タスクスキップが許可される唯一のケース
以下の技術的理由に該当する場合のみスキップ可能:
- 実装方針の変更により、機能自体が不要になった
- アーキテクチャ変更により、別の実装方法に置き換わった
- 依存関係の変更により、タスクが実行不可能になった

スキップ時は必ず理由を明記:
```markdown
- [x] ~~タスク名~~（実装方針変更により不要: 具体的な技術的理由）
```

### タスクが大きすぎる場合
- タスクを小さなサブタスクに分割
- 分割したサブタスクをこのファイルに追加
- サブタスクを1つずつ完了させる

### tasklistの更新タイミング（必須）
- **フェーズが完了したら即座に `[x]` に更新する**
- 最後にまとめて更新することは禁止
- 各タスク・サブタスクが終わったら、そのタイミングで更新する

## フェーズ3: 品質チェックと修正

### DoD（完了条件）
- 全テストがグリーン
- リントエラーがない（プロジェクト全体）
- （UI変更がある場合）最終スクリーンショットで見た目を目視確認済み

> ⚠️ スクリーンショット確認は「最後にまとめてやる」ものではない。
> UIに変更を加えた各フェーズで、そのフェーズのDoDにスクリーンショット確認を含めること。
> このフェーズでは全体の最終確認のみ行う。

### タスク

- [ ] 全テスト実行
    - [ ] すべてグリーン確認

- [ ] リント実行（新規ファイル）
    - [ ] 新規作成したファイルに対してリント実行
    - [ ] エラーがあれば修正して再実行
    - [ ] エラーゼロ確認

- [ ] リント実行（プロジェクト全体）
    - [ ] プロジェクト全体に対してリント実行
        - backend: `docker compose exec backend bundle exec rubocop`
        - frontend: `docker compose exec frontend yarn lint`
    - [ ] 新規コードが既存コードに与えた影響を確認
    - [ ] エラーがあれば修正して再実行
        - backend: `rubocop -a` または `rubocop -A` で自動修正
        - frontend: `yarn lint --fix` で自動修正
    - [ ] エラーゼロ確認

- [ ] （UI変更がある場合のみ）最終スクリーンショットで見た目を目視確認
    - [ ] `visual-inspector` サブエージェント（`Agent(subagent_type="visual-inspector")`）でスクリーンショットを撮る
    - ⚠️ `npx playwright` やPlaywright ツールの直接呼び出しは禁止。必ず visual-inspector サブエージェントを使うこと
    - [ ] 全体のデザイン・レイアウトが意図通りか確認
    - [ ] 問題があれば修正して再確認
